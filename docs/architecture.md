# Architecture

## Context

ParkEase is a microservice architecture for smart urban parking. The system orchestrates map discovery, real-time occupancy, booking, payment, and owner analytics.

## Services

- `api-gateway`: unified API, auth token issuing, workflow orchestration
- `map-service`: parking catalog, geo search, dynamic map metadata
- `sensor-service`: occupancy stream ingestion, plate recognition, spot reservation state
- `booking-service`: booking lifecycle, extension, cancellation
- `payment-service`: payment charge, auto-charge flow
- `navigation-service`: route building and indoor guidance
- `owner-service`: owner cabinet, tariff management, parking statistics
- `analytics-service`: KPI, hourly load, revenue, forecast, sharding plan
- `notification-service`: push/SMS/email/telegram notification queue

## Data Layer

- PostgreSQL: transactional data
- TimescaleDB: sensor telemetry and time-series metrics
- Redis: fast cache / transient state

## Messaging

- MQTT (Mosquitto): sensor telemetry stream channel
- RabbitMQ: async event fan-out for workflows

## Main Workflow

1. User calls `POST /workflow/find-and-book` on gateway
2. Gateway asks map service for nearest available parking
3. Gateway requests free spots from sensor service
4. Booking is created in booking service
5. Payment is charged in payment service
6. Spot is reserved in sensor service
7. Route is generated by navigation service
8. Notification is sent and analytics is updated

## Quality Targets

- Spot status update latency < 5s
- Booking creation latency < 3s
- Logical sharding strategy to support 100000+ spots
